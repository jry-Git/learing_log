A. 计算机基础 & 网络（阶段 B 会系统学，现在先混个脸熟）
名词
一句话：它到底是什么
掌握程度 + 会了的标准
学它看什么
HTTP 请求 / 响应报文
浏览器和服务器之间「写信」的固定格式。请求 = 请求行(方法 + URL + 版本) + 请求头 Header + 请求体 Body；响应 = 状态行(状态码) + 响应头 + 响应体。
L2 能解释｜按 F12 打开网络面板，能指出一个真实请求的 URL、Method、Header、Body 分别在哪；能说清 Content-Type 和 Cookie 放在哪一部分。
B 站搜「HTTP 报文格式」；小林 coding 网站 HTTP 篇
HTTP 状态码
服务器给你的「回执编号」：200 成功、301/302 重定向、400 请求写错、401 没登录、403 没权限、404 找不到、500 服务器崩了。
L2 能解释｜不查资料能说出上面 8 个码分别代表什么，并能说出 301 和 302 的区别。
搜索「HTTP 状态码大全」，10 分钟看完
GET / POST / 幂等
GET 是「取数据」，参数跟在 URL 后面；POST 是「提交数据」，参数放在 Body 里。幂等 = 做一次和做一百次结果一样。
L3 能动手｜能说出至少 3 条 GET 与 POST 的区别，并能解释「为什么说 GET 幂等、POST 不幂等」。
小林 coding「GET 与 POST 的区别」
HTTPS / TLS
HTTP 的加密版本，防止中间人窃听和篡改，靠 CA 证书确认「你访问的真是这家网站」。
L1 知道即可｜能说清「HTTPS = HTTP + TLS 加密 + 证书验身份」，不必背握手细节。
B 站搜「HTTPS 原理 动画」
TCP 三次握手 / 四次挥手
两台机器建立连接和断开连接时的「打招呼流程」。
L2 能解释｜能画出流程图，并回答「为什么是三次而不是两次」「为什么断开要四次」。
B 站「湖科大教书匠 计算机网络」TCP 章节
Cookie / Session / Token(JWT)
解决「服务器怎么知道这次请求是谁发的」。Cookie 存在浏览器，Session 存在服务器，Token 是一张自带信息的加密通行证。
L3 能动手｜能在自己的项目里实现一次「登录成功发 Token，之后请求带 Token 校验」的完整流程。
B 站搜「JWT 登录 实战 Spring Boot」
进程 / 线程 / 协程
进程 = 一个正在运行的程序（有独立内存）；线程 = 进程里的执行单元（共享内存）；协程 = 用户态的轻量线程，切换极廉价。
L2 能解释｜能说清三者区别、各自开销，以及「为什么多线程会有线程安全问题」。
B 站搜「进程 线程 协程 区别」
死锁
两个线程互相握着对方要的资源不放，谁也走不下去。
L2 能解释｜能说出死锁的 4 个必要条件，并说出至少 2 种预防/破解办法。
王道考研 操作系统「死锁」章节
IO 多路复用（select / epoll）
一个线程同时盯着成千上万个网络连接，谁有数据就处理谁——这是 Redis、Nginx 快的核心原因之一。
L1 知道即可｜能说出「Redis 单线程为什么还这么快」的答案里包含 IO 多路复用。
小林 coding「IO 多路复用」
虚拟内存 / 分页
操作系统给每个进程的「内存幻觉」：每个进程都以为自己独占一整块连续内存，实际由 OS 偷偷映射到物理内存。
L1 知道即可｜知道这个概念存在、知道有「缺页」这回事即可。
王道考研 操作系统「内存管理」
DNS / 域名解析
把 www.baidu.com 翻译成 IP 地址的那套系统。
L1 知道即可｜能说出「输入网址后第一步是 DNS 解析」。
B 站搜「DNS 解析过程」

JDK / JRE / JVM
JDK = 开发工具包（含编译器 javac，给开发者用）；JRE = 运行环境（给用户跑程序用）；JVM = 真正执行字节码的虚拟机。三者是包含关系：JDK ⊃ JRE ⊃ JVM。
L2 能解释｜能一句话说清三者关系，知道自己该装的是 JDK 17。

Maven
Java 的「依赖管家 + 构建工具」。你只要在 pom.xml 里写清楚要用哪些库，它自动下载、自动编译、自动打包。
L3 能动手｜能新建 Maven 项目、在 pom.xml 里加一个依赖并成功下载、能执行 mvn package 打出 jar 包。
B 站搜「Maven 入门 黑马」
依赖 / 依赖管理 / 依赖冲突
依赖 = 你直接拿来用的别人写好的库（比如 Spring、MySQL 驱动）。你用的库又会依赖别的库，这叫传递依赖；两个库要求同一个 jar 的不同版本，就是依赖冲突。
L3 能动手｜会用 mvn dependency:tree 查看依赖树，能定位并排除一个冲突依赖。
B 站搜「Maven 依赖冲突 解决」
jar / war 包
Java 的打包格式。jar 是普通程序包（Spring Boot 内嵌服务器就用它）；war 是传统 Web 应用包，要丢进外部 Tomcat 里跑。
L1 知道即可｜知道 Spring Boot 打出来的是 jar，直接 java -jar 就能跑。
随 Maven 一起学会即可
Servlet
Java 官方规定的「处理 HTTP 请求的小程序」规范。它本身不监听端口，只负责：拿到请求 → 处理 → 返回响应。真正监听端口的是 Tomcat。
L2 能解释｜能自己写一个 HelloWorld Servlet（继承 HttpServlet，重写 doGet），并用浏览器访问成功。
B 站搜「Servlet 入门 尚硅谷 / 黑马」
Servlet 生命周期
容器启动时 init() 执行一次 → 每来一个请求就走一次 service()（内部按方法分发到 doGet/doPost）→ 容器关闭时 destroy() 执行一次。关键推论：Servlet 是单例多线程的，所以在里面定义可变的成员变量会有线程安全问题。
L2 能解释｜能说出三阶段名称与调用次数，并能回答「为什么 Servlet 里不该定义成员变量」。
同 Servlet 教程的生命周期小节
Tomcat
一个 Servlet 容器 / 应用服务器。它干的活：监听 8080 端口 → 接收 HTTP 请求 → 按配置找到对应 Servlet → 把结果写回浏览器。你写的代码跑在它肚子里。
L3 能动手｜能本地启动 Tomcat，把一个 Web 项目部署上去并在浏览器访问成功。
B 站搜「Tomcat 安装 部署 黑马」
Web 服务器 vs 应用服务器
Nginx 是 Web 服务器：擅长发静态文件、做反向代理和负载均衡，不跑业务代码。Tomcat 是应用服务器：负责跑 Java 业务代码。生产环境通常是 Nginx 挡在前面，Tomcat 躲在后面。
L1 知道即可｜能说清「Nginx 和 Tomcat 谁在前、谁在后，各自干嘛」。
B 站搜「Nginx 反向代理 入门」
RESTful API
一种接口设计风格：用 URL 表示资源，用 HTTP 方法表示动作。例如 GET /users/1 查用户、POST /users 新增、DELETE /users/1 删除。
L3 能动手｜能为一个「文章模块」设计出一套符合 REST 风格的接口，并写清楚请求参数和返回结构。
B 站搜「RESTful 接口设计规范」
JSON
前后端传数据最常用的文本格式，长得像 {&#x201C;id&#x201D;:1,&#x201C;name&#x201D;:&#x201C;张三&#x201D;}。
L3 能动手｜能手写合法 JSON，能在 Java 里完成 对象 ↔ JSON 的互相转换（Jackson / Fastjson）。

端口 / localhost / 8080
IP 定位到机器，端口定位到机器上的某个程序。localhost = 本机（127.0.0.1），8080 是 Tomcat 默认端口，所以本地项目常访问 localhost:8080。

索引
数据库的「目录」。没有索引就全表扫描，有索引能直接定位。代价是占空间、拖慢写入。
L3 能动手｜能判断一张表该建哪些索引，能说出哪些写法会导致索引失效。

B+ 树 / 聚簇索引 / 回表
MySQL 索引的底层数据结构是 B+ 树（矮胖的多叉树，适合磁盘）。主键索引的叶子节点存整行数据，叫聚簇索引；普通索引叶子节点只存主键值，所以查完还要再查一次主键，这叫回表。
L2 能解释｜能说清「为什么 MySQL 用 B+ 树不用二叉树」「什么叫回表，怎么避免」。
小林 coding「B+ 树 / 索引结构」
事务 ACID
一组操作要么全成功要么全失败。原子性、一致性、隔离性、持久性。典型例子：转账，扣钱和加钱必须同时成功。
L2 能解释｜能说出 ACID 四个词分别什么意思，能举一个生活中的例子。
小林 coding「事务隔离级别」
隔离级别 / 脏读·不可重复读·幻读
多个事务同时跑时互相影响的程度。读未提交 → 读已提交 → 可重复读(MySQL 默认) → 串行化，越往后越安全越慢。
L2 能解释｜能说出四种级别和三种问题，知道 MySQL 默认是可重复读。
同上
MVCC
多版本并发控制：同一行数据保留多个历史版本，读的时候读旧版本，所以「读不阻塞写、写不阻塞读」。
L2 能解释｜能说清 MVCC 靠 undo log + ReadView 实现，以及它解决了什么问题。
小林 coding「MVCC 原理」
行锁 / 表锁 / 间隙锁
锁的粒度。行锁只锁一行（并发高），表锁锁整张表（并发低），间隙锁锁住一段「缝隙」防止别人插入（用来解决幻读）。
L2 能解释｜能说出三种锁的使用场景，知道「update 忘加索引会锁全表」。
小林 coding「MySQL 锁」
Explain / 慢查询
Explain 是让 MySQL 告诉你「这条 SQL 打算怎么执行」；慢查询日志记录执行超过阈值的 SQL。两者合起来是 SQL 调优的入口。
L3 能动手｜拿到一条慢 SQL，能用 Explain 看出有没有走索引、扫描了多少行，并给出改写方案。
B 站搜「MySQL Explain 详解 / 慢查询优化」
缓存穿透 / 击穿 / 雪崩
穿透 = 查一个根本不存在的数据，每次都打到数据库；击穿 = 一个热点 key 刚好过期，瞬间大量请求打到数据库；雪崩 = 大批 key 同时过期。
L3 能动手｜能说出三者的区别和各自解法（布隆过滤器 / 互斥锁或逻辑过期 / 随机过期时间），并在项目里至少落地一种。
B 站「黑马 Redis 从入门到实战」缓存章节
Redis
内存数据库，读写极快，主要当缓存用；也提供分布式锁、排行榜、限流等能力。
L3 能动手｜能用 Redis 做缓存、能用 Redisson 实现分布式锁、能处理缓存三兄弟。

分布式锁
多台机器部署时，JVM 里的 synchronized 就管不住别的机器了，需要一个所有机器都认的外部锁——通常用 Redis 或数据库实现。
L3 能动手｜能用 Redisson 写出一把可用的分布式锁，并说出「看门狗自动续期」是干嘛的。
同 Redis 课程；搜索「Redisson 分布式锁」
消息队列 MQ（Kafka / RabbitMQ / RocketMQ）
一个「暂存消息的管道」。服务 A 把消息丢进去就不管了，服务 B 慢慢消费。用来削峰、解耦、异步化。
L2 能解释（大三下升 L3）｜能说清「为什么要用 MQ」「消息重复消费和消息丢失怎么解决」。

幂等
同一个操作执行一次和执行一百次，结果完全一样——不会重复扣款、不会生成两条订单。是分布式系统的基本功。
L3 能动手｜能说出至少 3 种幂等实现方案（唯一索引、Token 机制、状态机、分布式锁）。

Spring
Java 后端的事实标准框架。核心就两件事：IOC（帮你创建对象）和 AOP（帮你无侵入地加功能）。

IOC / DI（控制反转 / 依赖注入）
以前你自己 new 对象，现在你把对象的创建交给 Spring 容器，需要时用 @Autowired 直接拿。这就是控制反转；容器把依赖「注入」给你，就是依赖注入。

AOP（面向切面编程）

大模型 / LLM
就是 ChatGPT、通义千问、DeepSeek 这类「读了海量文本、能理解和生成语言」的模型。你不是去训练它，而是去调用它、把它接进业务系统。

Token
模型计费和计量的最小单位，粗略理解成「字/词碎片」。中文一般 1 个字约 1–2 个 token。它决定了你的成本和上下文长度上限。

Prompt / Prompt 工程
你给模型的指令。同样的模型，prompt 写得好不好，效果能差一个档次。核心技巧：给角色、给上下文、给示例、给输出格式要求。
L3 能动手｜能写出一个让模型稳定返回 JSON 的 prompt，并做异常兜底。

Temperature
控制模型输出的随机程度。越低越确定、越稳定（适合抽取、分类），越高越发散（适合创意写作）。

模型 API 文档
RAG（检索增强生成）
模型不知道你们公司内部的知识，怎么办？先把文档切成小块、转成向量存起来；用户提问时先检索出相关片段，塞进 prompt 再让模型回答。这就是 RAG，是目前企业落地最多、岗位缺口最大的方向。
L3 能动手｜能从零搭出一个「上传 PDF → 能问能答」的 RAG 系统，并能说出每个环节的作用和可优化点。
B 站搜「RAG 实战 教程」；deeplearning.ai《Advanced RAG》
Embedding / 向量
把一段文字变成一串数字（向量），语义相近的文字，向量距离也近。这是「按意思检索」而不是「按关键词检索」的基础。
L2 能解释｜能说清向量检索和关键词检索的区别，知道怎么选 embedding 模型。
B 站搜「Embedding 向量 原理」
向量数据库（Milvus / pgvector / FAISS）
专门存向量、做相似度检索的数据库。pgvector 是 PostgreSQL 的插件，上手最简单，推荐你从它开始。
L3 能动手｜能把一批文本存进去，并按相似度召回 top-K。
B 站搜「pgvector 入门」；Milvus 官方文档
召回 / 重排
召回 = 用向量快速捞出一批候选（快但不够准）；重排 = 用一个更精细的模型把候选重新排序（慢但准）。两阶段组合是工业界标配。
L2 能解释｜能说清为什么要分两阶段，以及各自用什么模型。
同 RAG 课程
幻觉
模型一本正经地编造不存在的事实。这是 RAG 要解决的核心问题，也是面试官最爱问的。
L2 能解释｜能说出至少 3 种缓解幻觉的手段（ grounding、引用原文、低 temperature、拒答机制、评测兜底）。
搜索「大模型 幻觉 缓解 方法」
Agent（智能体）
不只是「问一句答一句」，而是让模型自己规划步骤、调用工具、多轮迭代直到完成任务。比如「帮我查这周的销售额并生成图表」。
L3 能动手｜能实现一个能调用 2–3 个工具、能多轮对话完成任务的 Agent。
B 站搜「Agent 开发 实战 LangGraph」
Function Calling / Tool Use
让模型不只是「说」，而是「做」：你告诉模型有哪些函数可用，模型决定调用哪个并给出参数，你去真正执行再把结果喂回去。
L3 能动手｜能让模型成功调用你自己写的 Java/Python 函数。
各家模型 API 文档都有专门章节
MCP
Model Context Protocol，给模型接外部工具/数据源的通用接口标准，可以理解为「AI 应用的 USB 接口」。
L1 知道即可（新兴标准，了解即可）｜知道它解决什么问题。
搜索「MCP 协议 入门」
LangChain / LangGraph
AI 应用开发的工具库。LangChain 提供各种组件拼装；LangGraph 用来编排有循环、有分支的复杂 Agent 流程。Python 生态，是 AI 岗的高频关键词。
L2 能解释（Python 侧）｜能读懂示例代码并改造；注意：你走 Java 主线时优先学 Spring AI。
LangChain / LangGraph 官方文档
Spring AI / Spring AI Alibaba
Spring 官方出的 AI 开发框架，让你用写 Spring 的方式接入大模型、向量库、RAG、工具调用。对 Java 主线的人来说，这是投入产出比最高的一条路。
L3 能动手｜能用 Spring AI 在自己的 Spring Boot 项目里接上大模型，实现对话 + 工具调用。
Spring AI 官方文档；B 站搜「Spring AI 教程」
评测 / 可观测（Eval / Observability）
AI 应用不能靠「感觉挺好」上线。评测 = 用一批测试问题量化回答质量；可观测 = 记录每次调用的链路、耗时、成本，出问题能定位。这是「校园 demo」和「企业级系统」最大的差距。
L3 能动手｜能为自己的 RAG 项目建一个 20 条的评测集，并记录每次调用的成本与耗时。
搜索「RAGAS 评测」「Langfuse 可观测」

9. 最后三句话
不要追求学完，要追求能交付。 完成 1 个能讲 15 分钟的项目，比看完 10 门课有用 10 倍。
AI 是你的放大器，不是你的替代品。 你越懂底层，AI 让你越快；你什么都不懂，AI 只会让你更心虚。
计划的价值在于执行，不在于完美。 落后一天照常继续，别推翻计划重来——重来是最常见的失败方式。
