## 学到的（用自己的话写）

- **`i * i <= n` 代替开根号**：判断质数只需循环到 √n，不用 `Math.sqrt`，
  两边平方写成 `i * i <= n` 就行。比 `i <= n / 2` 快几百倍。
- **`continue` 几乎总是配 `for` 用**：`continue` 会跳过它后面的所有代码。
  在 `while` 里，自增语句 `num++` 在它后面 → 被跳过 → **死循环**。
  而 `for` 的 `n++` 是循环结构自带的，不在循环体里，`continue` 跳不过去，所以安全。
- **`case 穿透`**：switch 里忘记写 `break`，会继续执行下一个 case 的代码块，
  直到遇到 `break` 或 switch 结束。多个空 case 连续落下共享一个分支，是它的正确用法。
- **方法重载的判断标准**：方法名相同 + **参数列表不同**（个数 / 类型 / 顺序）。
  **与返回值类型无关**——`int add(int,int)` 和 `double add(int,int)` 会编译报错。
- **`static` 方法不能直接调用非 `static` 方法**：`main` 是 static，
  所以我定义的 `add` 也必须加 `static` 才能调用。
- **`continue` 不能替代 `if`**：它只是换了一种写法（筛掉不符合的，让主逻辑不用包在 if 里），
  条件判断还是要用 if。

## 卡住的地方 + 怎么解决的

- **`isPrime` 把 4 判断成质数**（真 BUG）
  → 循环条件写的是 `while (i < n / 2)`，而 4 的唯一因子 2 **正好等于** n/2，被 `<` 漏掉了。
  → 改成 `i <= n / 2`（最终用 `i * i <= n`）。
  → **教训：写完循环一定要测边界值 —— 0、1、2、最小值、最大值。**

- **`n < 2` 没处理**（第二个 BUG）
  → 0、1、负数都会因为循环不执行而被判成「是质数」，但 1 不是质数。
  → 在循环前加守卫：`if (n < 2) { ...不是质数...; return; }`

- **continue 版静默不执行**（第三个 BUG，最阴险）
  → 复用了上一个循环的变量 `num`，此时它已经是 101，第二个循环 `101 <= 100` 直接为 false，
    **一次都没跑**；而且后面没有 `println`，完全看不出来。
  → 而且就算重置了 num，`continue` 会跳过 `num++` → 死循环。
  → **教训：① 复用变量前先重置 ② 没有输出的代码等于没写 ③ continue 配 for 用**

- **九九乘法表方向反了**
  → 最初写 `for (j = i; j <= 9; j++)` 得到的是上三角；
    课本版是第 i 行有 i 项，即 `for (j = 1; j <= i; j++)`。

- **`Math.random()` 生成 1~100 随机数**
  → `(int)(Math.random() * 100 + 1)`：`Math.random()` 返回 [0,1)，
    ×100 → [0,100)，+1 → [1,101)，转 int → 1~100。
