## 关键改动 & 踩坑

1. **构造器链重构（修之前 bug）**
   - 旧版 `Student(String name)` 没把 name 赋给字段，且链里写死 `"TOM"`/空格，导致 `new Student("Sam")` 拿到错误 name。
   - 改为 **所有构造器收敛到三参全构造器** `Student(int id, int age, String name)`，统一在里面赋值；`Student(String name)` → `this(0, 0, name)` 真正把参数传下去 → `name="Sam"` 正确。
   - 顺带理清：`this()` 调用本类其他构造器必须放首行；构造器只能重载、不能被重写；名字必须与类名相同。

2. **封装（private 字段 + getter/setter）**
   - 三个字段 `id / name / age` 设为 `private`，提供 `getId / getName / getAge` 和 `setXxx`；封装意义 = 隐藏实现 + 控制赋值 + 提高安全性。

3. **异常（今天新学重点）**
   - `setAge` 加校验：`if (a < 0) throw new IllegalArgumentException("年龄非法");`
   - 初版写成「先 `this.age = 输入值` 再检查」→ 审查发现非法值会先污染字段；改为「先读局部变量 `a`、检查通过再 `this.age = a`」。
   - 区分 **`throw`（抛出动作）** vs **`throws`（方法签名声明受检异常）**；`IllegalArgumentException` 是 `RuntimeException` 子类（**非受检**，编译不强制处理），做参数校验最轻量。
   - 对比：`println` 报错只是打印、非法值照样进去；抛异常会中断方法、强制调用方重视。

4. **待优化（非必须，已提醒）**
   - `Scanner scan` 当**实例字段**会随每个对象创建、且从不 `close`，浪费；建议放 `main` 局部变量。
   - 无参 `setXxx()` + 键盘读虽能跑，但违背 setter「带参赋值」惯例（面试减分）；练习阶段可接受。
